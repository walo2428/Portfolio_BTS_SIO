Gestion des risques

Critique — R1

Perte données Nextcloud — Volumes Docker persistants db_data & nextcloud_data. Vérification survie après docker-compose down/up.

Élevé — R2

Port bloqué par pare-feu — ufw allow 9090/tcp && ufw allow 8080/tcp. Vérification ufw status + netstat -tlnp.

Moyen — R3

Conflit versions Docker — Versions fixes dans docker-compose.yml : mariadb:10.6, nextcloud:27. Éviter les tags "latest".

Faible — R4

Services inaccessibles après reboot — restart: always dans docker-compose.yml + systemctl enable docker.

Active Directory IRIS — Authentification centralisée

Windows Server 2022 · 6 VLANs · 802.1X · 14 scripts PowerShell · 8 phases · 09 au 20 mars 2026

Objectifs du projet

Le campus IRIS Nice disposait d'une infrastructure Cisco (routeur 1941W, switch 2960-S, borne Wi-Fi C9105AXI) mais d'aucune gestion centralisée des utilisateurs, d'aucune authentification individuelle et d'aucun partage de fichiers sécurisé. Le projet ajoute un service d'authentification centralisé sur cet écosystème existant.

Centraliser les identités : domaine iris.local, 9 OUs, 9 groupes de sécurité et 21 comptes nominatifs

Services réseau : DHCP centralisé sur Windows Server avec 5 scopes par VLAN, DNS intégré à l'AD

Partages et GPO : matrice de droits SMB/NTFS par groupe, répertoires personnels, lecteurs H: S: P: A: mappés par GPO Préférences

Authentification 802.1X : NPS RADIUS adossé à l'AD et à une autorité de certification interne, avec attribution dynamique du VLAN

Flux d'authentification 802.1X
1
Connexion en VLAN 99 (PRE-AUTH)

Le client Wi-Fi ou filaire n'a accès qu'au DHCP tant qu'il n'est pas authentifié

2
Requête EAP vers le switch ou la borne

L'équipement ne vérifie rien lui-même : il encapsule la demande dans un Access-Request RADIUS

3
Contrôle par NPS (SRV-DC01)

Équipement déclaré comme client RADIUS, puis vérification des identifiants dans l'Active Directory

4
Politique réseau selon le groupe

GRP-WiFi-SISR → VLAN 10 · GRP-WiFi-Profs → VLAN 20 · GRP-WiFi-Admin → VLAN 30 (Tunnel-Pvt-Group-ID, RFC 3580)

5
Placement dans le VLAN et adressage

Le client reçoit son IP du scope DHCP du VLAN attribué ; le VLAN 40 Guest reste isolé des services internes
