Matrice Eisenhower — Réévaluation Sprint 3

Exemple concret : l'ouverture des ports était classée « priorité moyenne » le lundi matin du sprint 3. Dès le mardi, aucun test de connexion n'était possible sans les ports ouverts — la tâche est passée immédiatement en critique / faire maintenant.

Urgent + Important

Ouverture ports 9090/8080 — Faire maintenant. Sans les ports, aucun test possible.

Urgent + Important

Volumes Docker persistants — Faire maintenant. Perte de données sans volumes.

Non urgent + Important

Documentation GitHub README — Planifier (sprint 4). Livrable obligatoire rappelé par Yan.

Reporter

HTTPS / SSL Nextcloud — Dépendance Traefik (Julien) — non disponible avant fin sprint 4.

Gestion des risques

Critique — R1

Perte données Nextcloud — Volumes Docker persistants db_data & nextcloud_data. Vérification survie après docker-compose down/up.

Élevé — R2

Port bloqué par pare-feu — ufw allow 9090/tcp && ufw allow 8080/tcp. Vérification ufw status + netstat -tlnp.

Moyen — R3

Conflit versions Docker — Versions fixes dans docker-compose.yml : mariadb:10.6, nextcloud:27. Éviter les tags "latest".

Faible — R4

Services inaccessibles après reboot — restart: always dans docker-compose.yml + systemctl enable docker.

Zéro bug bloquant — Scénario de recette T01-T09 : 0 bug critique, services stables.

Tests validés : 9/10 — T10 (HTTPS) reporté en sprint futur — dépendance externe documentée.

Documentation : 4/4 sprints — README GitHub mis à jour chaque fin de sprint, commits horodatés.
